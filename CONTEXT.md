# Domain Glossary — Git for Prompts

This document defines the canonical vocabulary used across the codebase, user interface, and documentation for Git for Prompts.

---

### Core Entities

#### Prompt
A top-level prompt template entity. It represents a specific AI instruction goal (e.g., "Customer Support Agent" or "Email Summarizer"). It holds metadata (name, description, owner) but does not store the prompt text directly.

#### Version
An immutable, historical snapshot of a Prompt's content. Every edit saves a new Version, auto-incrementing the version number (1, 2, 3...). Once created, a version cannot be modified.

#### Commit Message
A user-provided short description attached to a Version, explaining what changes were made (e.g., "Adjusted tone to be more professional").

#### Test Case
An assertion benchmark attached to a Prompt. It contains an `inputText` (the simulated user message) and `expectedCriteria` (natural language instruction on what the output must contain, e.g., "Must offer a refund and sign off with Support Team").

#### Test Result
The outcome of running a prompt Version against a Test Case. It records whether the version `passed` or `failed`, the `actualOutput` generated by the AI model, and an optional confidence score.

#### API Key
A cryptographically hashed token that enables developer applications to programmatically fetch the latest active prompt version via the public API endpoints.

---

### User Interface Concepts

#### Playground (Demo)
A client-side, ephemeral simulation of the Git for Prompts workspace. Located on the public landing page, it allows unauthenticated users to edit prompts, see diffs, and run simulated test executions entirely in browser memory.

#### Interactive Tour Panel
A visual showcase on the landing page composed of vertical feature tabs on the left and an animated motion demo canvas on the right that explains product capabilities.

#### Split-Screen Wipe
A draggable visual separator on the diff canvas where sliding the cursor sweeps between the original (v1) and modified prompt versions to highlight line differences.

#### Model Flow Graph
A visual node flow diagram depicting input parameters feeding into the LLM node and executing assertion checklists, showing green/red checkmarks dynamically.
