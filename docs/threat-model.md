# Threat Model — Git for Prompts

Comprehensive security threat model evaluation for Git for Prompts, classifying attacker personas, protected assets, vulnerability vectors, and mitigation requirements.

---

## 1. Attacker Personas

1. **Unauthenticated Internet Attacker**: Scans public IP space, targets `/api/v1/` endpoints, attempts brute-force API key discovery, probe for SSRF endpoints, and attempt DDoS/resource exhaustion.
2. **Authenticated Malicious User**: Registered Clerk account attempting cross-tenant data access (IDOR / BOLA) to read/edit another user's prompts, versions, test cases, or API keys.
3. **Compromised API Key Holder**: Possesses a leaked `gfp_live_*` API key; attempts scope escalation, key enumeration, or prompt tampering.
4. **Malicious Webhook Destination / Server**: Webhook receiver endpoint controlled by an attacker designed to execute Server-Side Request Forgery (SSRF), DNS rebinding, internal infrastructure probing (169.254.169.254), or slow-loris HTTP responses.
5. **Malicious Webhook Owner**: Registering webhooks pointing to internal network IP ranges (`127.0.0.1`, `10.0.0.0/8`, `192.168.0.0/16`) to scan backend topology.
6. **Malicious Prompt Content Injector**: User submitting prompt contents designed to trick AI evaluators, bypass safety constraints, or exhaust system resources during evaluation.
7. **Malicious AI Model Output**: Untrusted text generated by third-party LLMs (Groq/OpenRouter) containing prompt injection payloads, system prompt extraction instructions, or XSS vectors targeting Monaco / rendered markdown UI.
8. **Compromised Third-Party Provider**: Outage or compromise of Clerk, Groq, OpenRouter, or Upstash Redis.
9. **Abusive Legitimate User**: Account flooding the system with millions of versions, concurrent evaluations, or giant prompt payloads to exhaust database disk space and LLM token budgets.

---

## 2. Asset Inventory & Protection Requirements

| Asset | Sensitivity | Primary Threat | Required Security Control |
|-------|-------------|----------------|---------------------------|
| Private Prompts & Bundles | High | Unauthorized Read / Data Leakage | Mandatory DB-level tenant isolation (`ownerId`) |
| Version History | High | Version Tampering / Overwrites | Immutable table design (`versions`), append-only enforcement |
| Test Cases & Results | Medium | Unauthorized Access / Poisoning | Owner authorization check on all CRUD operations |
| API Keys | Critical | Key Disclosure / Compromise | One-way SHA-256 storage (`keyLookupHash`), display prefix only |
| Webhook Secrets | Critical | Signature Forgery | High-entropy HMAC signing key |
| LLM Provider Credentials | Critical | API Key Theft / Financial Loss | Server-only env variables (`GROQ_API_KEY`, `OPENROUTER_API_KEY`) |
| Database Integrity | Critical | SQL Injection / Data Corruption | Drizzle ORM parameterized queries, transaction locks |
| LLM Budget & Resources | High | Denial of Wallet / Token Exhaustion | Rate limiting, token bounds, fan-out concurrency limits |

## 3. Vulnerability Vector Evaluation Matrix

| Risk Category | Evaluated Vulnerability | Severity | Target Mitigation |
|---------------|-------------------------|----------|-------------------|
| **Auth Bypass** | Missing Clerk keys in production falling back to `'user_local_dev'` | **CRITICAL** | Production environment check to fail closed if Clerk keys are absent (`NODE_ENV === 'production'`). |
| **SSRF** | Outbound webhooks fetching arbitrary URLs without IP validation | **HIGH** | DNS resolution validation, blocking loopback (`127.0.0.1`), private RFC1918 IPs, and cloud metadata (`169.254.169.254`). HTTPS enforce. |
| **IDOR / BOLA** | Fetching/modifying versions or test cases without owner validation | **HIGH** | Enforce `ownerId = auth().userId()` on every read/write query. |
| **Race Conditions** | Concurrent version insertions assigning duplicate `versionNumber` | **HIGH** | Retain mandatory `pg_advisory_xact_lock` per prompt ID during version insertion. |
| **API Key Abuse** | Stolen API keys used indefinitely without expiration or revocation | **MEDIUM** | Add key revocation (`revokedAt`), expiration (`expiresAt`), and permission scopes. |
| **Resource Exhaustion** | Oversized prompt content or unlimited test case fan-out | **MEDIUM** | Hard byte limits (`MAX_PROMPT_CONTENT_BYTES = 100KB`), max test cases (1,000 per prompt), max fan-out bounds. |
| **Prompt Injection** | LLM output manipulating evaluator logic | **MEDIUM** | Delimited system prompts in evaluator instructions; untrusted model outputs isolated from control code. |
| **XSS** | Untrusted prompt content rendered in Monaco / web UI | **LOW** | Escape dynamic inputs, use strict React DOM bindings, no `dangerouslySetInnerHTML`. |
